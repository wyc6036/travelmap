
## 修复：编辑态改尺寸后模块大小无变化
- 根因：`web/js/ui.js` 的 `applySize` 给 `.widget` 元素设置了 CSS 变量 `--w`/`--h`，但 `web/css/widget.css` 里只有容器 `.grid--main` 的 `grid-template-columns`/`grid-auto-rows`，**没有任何规则消费这两个变量让卡片跨格**，导致每个组件永远只占 1×1，无论默认还是改尺寸都不变。
- 修复：在 `web/css/widget.css` 的 `.widget` 规则中补上 `grid-column: span var(--w, 1); grid-row: span var(--h, 1);`。
- 验证（Playwright + Chromium）：
  - 默认 recent(2×1) 实测 596×230 px，`grid-column: span 2`。
  - 编辑态改为 3×2 后，实测 901×474 px，`grid-column: span 3`，宽高真实变化，无 JS 错误。
  - 完整回归测试 14/14 通过。

## 修复（二）：海报墙模块变长条时照片被拉成横条
- 根因：海报墙网格在 `poster.css` 里写死为 4 列 × 4 行。模块被拉成宽长条（墙宽高比远大于 1）
  时，4 行被压成每行几十像素的扁格，每张照片所在的格子都变成横条（实测 960×180 时
  1×1 格 ≈ 240×45 ≈ 5:1）。`object-fit: contain` 只解决裁切，没解决格子形变。
- 修复：让墙随自身宽高比改版（用 `ResizeObserver` 在 `poster.js` 写回 class，纯 CSS 无法引用自身宽高比）。
  - 宽高比 > 1.5 → `.posterwall--wide`：5 列 × 2 行，十块 1×1 均布，rows/cols=0.4 → 格子宽高比 ≈ 墙宽高比×0.4，长条下落在 0.6~2.0，不再成 5:1 横条。
  - 宽高比 < 0.75 → `.posterwall--tall`：2 列 × 5 行。
  - 其余（近方，含默认 2×2 磁贴）→ 保持原 4×4 精排版式，外观不变。
- 验证（Playwright 直连 CDN + 本机 8126 服务）：
  - 多种墙宽高比实测：方(0.98)/桌面 2×2(0.95) 保持 4×4（格 0.9~1.99）；宽 3×2(2.62)→5×2 格≈1.03；
    超宽(4.94)→5×2 格=2.0；竖 1×2(0.89) 保持 4×4。所有格宽高比 ≤ 2.1，全 0 报错。
  - 真实首页：把 poster 磁贴设为 3×2，墙宽高比 2.11，自动套 `posterwall--wide`（5×2），0 报错。
  - 完整 smoke 回归 14/14 通过，无回归。
- 收尾：删除临时 `web/poster-layout-test.html`，停止 8126 服务。

## 修复（六）：海报模块偶尔左右抖动
- 排查：用 Playwright 连续翻牌 7s 采样组件卡/单格的 getBoundingClientRect 水平位置与 posterwall 的 class —— 水平位置 0 跳变、class 始终为 `--wide` 未切换，
  排除「布局重排/响应式误触发」；确认是**翻牌 3D 合成层亚像素抖动**。
- 根因：`poster.js` 的 `flip()` 每次翻牌 `rec.rot += 180` 无限累加，rotateY 角度越大三角函数浮点精度越差，投影的 X 缩放出现亚像素漂移 → 左右抖。
- 修复（`web/js/poster.js`）：翻牌结束后用 `transitionend` 把累加角度 `% 360` 归零（360° 与 0° 视觉等价，瞬移不可见）；即时翻牌（首帧/换一批）也 `% 360` 保持有界。
  另在 `web/css/poster.css` 给旋转容器 `.pw__in` 加 `backface-visibility: hidden`，防止背面穿透闪烁（抖动的另一来源）。
- 验证：诊断脚本确认 rotateY 角度范围被钳制（≤360）、7s 内水平位置 0 跳变、0 报错；首页冒烟 14/14 通过，无回归。
