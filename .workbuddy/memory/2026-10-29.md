# 2026-10-29

## 首页小组件：模块唯一性（已添加的不再出现在待选列表）

需求：模块加到主页后从「待选择列表」消失，移除后才回来。

改动（只碰非地图模块，`web/js/ui.js` + `web/css/widget.css`）：
- 新增 `usedTypes()` / `availableTypes()`：以 `layout` 为唯一权威（含 `syncLayoutFromDom` 从 DOM 反推的状态），已占用的 type 不进列表。
- `openWidgetSheet` 拆出 `renderSheetList(rec)`：只渲染 `availableTypes()`；空列表给 `.wj-sheet__empty` 文案（替换 / 新增两套口径）。
- 替换面板标题改为「替换「<模块名>」」——列表里不再出现目标本身，靠标题交代当前对象。
- `addSlot()` 补唯一性兜底（`usedTypes().has(type)` → toast 拒绝），防止绕过 UI 重复添加。
- 「＋ 添加模块」瓦片：`addEl` 提升为模块级变量 + `refreshAddTile()`，在 `buildGrid` / `removeSlot` / 替换完成后同步；8 个全占用时 `disabled` + `.is-depleted`（opacity .55、not-allowed），文案改「已全部添加」，**瓦片不隐藏**（用户选型：保留但置灰不可点）。
- 移除后 `refreshAddTile()` 让瓦片恢复、该模块回到列表。

关键坑：
- **不要给替换目标开 exclude 例外**：最初 `availableTypes(rec.type)` 把目标从 used 里删掉，导致它自己出现在替换列表里（8 个全占用本该空态却列出 month）。目标本来就占用着那一格，天然不在「未占用」集合，直接无参调用即可。
- `DEFAULT_LAYOUT` 正好用满 8 个模块 → 默认状态下新增 / 替换列表都是空的，这是常态边界而非异常，空态文案必须交代「移除后可再次添加」。
- 历史脏数据（layout 里同 type 出现两次）不崩：两个卡都保留在首页，该 type 因 set 判定仍不可选；新添加无法再产生重复。

验收：`npm run preview:widgets-check`（第 ⑤⑥ 段已改写为唯一性断言，产物 `widgets-sheet-empty.png` / `widgets-sheet-one.png`，`widgets-sheet.png` 已删）。另跑临时脚本验了两个边界：移除全部 8 个→面板列全 8 项；localStorage 预置重复 type→不崩、只列 6 项。

## 首页小组件：8 个模块内容改造（P0 缺陷 → P1 空洞 → P2 增强）

背景：用户反馈"有些模块太空洞、有些太简陋"，并要求图片墙按我判断改。诊断结论是四个图片墙（recent/wishlist/collections/poster）同质化，且卡片只用「地名+国家+日期」这一层字段。

- **recent（2×1）**：`paintRecent` 改为按容器实测高度**逐张试插、放不下回退**（旧实现固定塞 6 张，2×1 只容 4 张 → 溢出 148px 被裁；620px 窄屏溢出 800+）。磁贴内不再塞「添加新足迹」瓦片（它会挤到第二行）。`placeCard` 新增 `badge:'total'` 显示记录总数。一张都放不下时保留第一张（宁可滚动不留白）。
- **layout.css**：删掉 `≤1200px` 的 `repeat(2, 1fr)` 硬规则 —— 620px 下模块通栏满宽，2 列会把卡拉到 274px 宽（图高 205 > 卡体 193）导致 recent 全空。交回 `auto-fill minmax(126px)`：291→2 列、560→3 列、596→4 列。
- **wishlist（1×1）**：从「缩小版足迹条带」改成**心愿卡**（`.wg`/`.wcard`，与 `.mcard` 分开命名）：封面 + 想去/已去角标 + 优先级星（`priority>0` 才显示）+ 名字 + 国家（已去补日期、想去补目标季，有值才显示）+ 底部「待出发/已实现」进度条。2 张整卡，不再露 1.6 张。
- **collections（1×1）**：从图片墙改成**记录概览**：总数 + 图/视频/笔记构成条 + 图例 + 最近一条缩略卡（点开直达那张图）。`clientHeight ≥ 300` 时追加「按地点分布」排行榜（行高 flex 等分，2×2 自动撑满）。—— 与 recent 分工：recent 讲"最近去哪"，collections 讲"积累了多少"。
- **poster（2×2）**：`posterPool()` 每地点**均匀采样最多 4 张** + 轮次交错；`poster.js` 首屏改为按池序轮流发牌、`pickNext` 排除与当前块同地点的图 → 5 地 10 块各 2 块（原来随机会出现成都 ×4）。卡头补「N 地 · N 张」。`.pw__meta` 改上下两行、地名 2 行 clamp（原来窄块里被截成「九…」）。
- **roulette（1×1）**：抽中后显示封面缩略（无图用类型色首字块）+ 「第 N 顺位」；未抽时留虚线「?」占位（避免默认态全空、抽中瞬间跳动）。
- **pending（1×1）**：每桶带一张代表图（`.pnd__thumb` 22px，`pendingBuckets` 新增 `noTimeThumb`/`noDateThumb`）；加载失败回退成色点。行高 32。
- **month（2×1）**：柱子按**季节**上色（春 --c5 / 夏 --c4 / 秋 --c1 / 冬 --c2，不新增色值）；零值月画 2px 基线（`!important` 覆盖内联 height:0，否则 9 个月是纯空白）；底部补「平均每月 N 次 · 最冷清 X 月」。
- **lastTrip（2×1）**：日期行加「N 天前」胶囊；三个数字改成「数字在上、单位在下」+ 竖分隔，撑住宽卡右侧。

关键坑：
- resize 时**必须重排内容**，不能只 `applySize`：recent/wishlist 的张数是按容器算的，只改 --w/--h 会留着宽屏的张数被裁。已加 `reflowWidgets = debounce(...)` 调 `renderHome()`。
- `data/travelmap.db` 里开发库媒体文件多在 MinIO 目录已清空 → 截图里大量渐变占位，验证缩略图布局要用内联 data-URI 图替换后再看。
- `priority/note/target` 在库里全是空/0，所有依赖它们的信息必须是「有值才显示」，不能当主信息。

验收：所有 8 卡 `scrollHeight-clientHeight === 0`（1440/1180/900/620 四档）；编辑态唯一性断言全过；2×2 的 collections 内容撑满（`437/437`，5 行地点分布）。
