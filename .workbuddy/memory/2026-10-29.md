## 首页小组件：模块唯一性（已添加的不再出现在待选列表）

需求：模块加到主页后从「待选择列表」消失，移除后才回来。

改动（只碰非地图模块，`web/js/ui.js` + `web/css/widget.css`）：
- 新增 `usedTypes()` / `availableTypes()`：以 `layout` 为唯一权威（含 `syncLayoutFromDom` 从 DOM 反推的状态），已占用的 type 不进列表。
- `openWidgetSheet` 拆出 `renderSheetList(rec)`：只渲染 `availableTypes()`；空列表给 `.wj-sheet__empty` 文案（替换 / 新增两套口径）。
- 替换面板标题改为「替换「<模块名>」」——列表里不再出现目标本身，靠标题交代当前对象。
- `addSlot()` 补唯一性兜底（`usedTypes().has(type)` → toast 拒绝），防止绕过 UI 重复添加。
- 「＋ 添加模块」瓦片：`addEl` 提升为模块级变量 + `refreshAddTile()`，在 `buildGrid` / `removeSlot` / 替换完成后同步；8 个全占用时 `disabled` + `.is-depleted`（opacity .55、not-allowed），文案改「已全部添加」，**瓦片不隐藏**（用户选型：保留但置灰不可点）。
- 移除后 `refreshAddTile()` 让瓦片恢复、该模块回到列表。

关键坑：
- **不要给替换目标开 exclude 例外**：最初 `availableTypes(rec.type)` 把目标从 used 里删掉，导致它自己出现在替换列表里（8 个全占用本该空态却列出 month）。目标本来就占用着那一格，天然不在「未占用」集合，直接无参调用即可。
- `DEFAULT_LAYOUT` 正好用满 8 个模块 → 默认状态下新增 / 替换列表都是空的，这是常态边界而非异常，空态文案必须交代「移除后可再次添加」。
- 历史脏数据（layout 里同 type 出现两次）不崩：两个卡都保留在首页，该 type 因 set 判定仍不可选；新添加无法再产生重复。

验收：`npm run preview:widgets-check`（第 ⑤⑥ 段已改写为唯一性断言，产物 `widgets-sheet-empty.png` / `widgets-sheet-one.png`，`widgets-sheet.png` 已删）。另跑临时脚本验了两个边界：移除全部 8 个→面板列全 8 项；localStorage 预置重复 type→不崩、只列 6 项。

## 首页小组件：8 个模块内容改造（P0 缺陷 → P1 空洞 → P2 增强）

- **roulette（1×1）**：抽中后显示封面缩略（无图用类型色首字块）+ 「第 N 顺位」；未抽时留虚线「?」占位（避免默认态全空、抽中瞬间跳动）。

## 心愿回访提醒（顶栏铃铛 + 三分支浮层）+ B 类心愿日期改日期框

需求：心愿的日期过了 → 主页右上角出现提醒标识 → 点开问「去了没」→ 去了再问要不要加媒体；没去则问要不要换时间（改日期）或不去了（移出清单+清日期）。用户选型：确认状态存后端 `wish_annotations.checked_at`；「不去了」= 移出清单并清空日期（保留地点记录，可在「已取消」找回）。用户中途纠偏：**B 类也要做，把 target 文本框改成日期框，一并修改**（我原提议只做 A 类被否）。

### 数据层（src/db.js）
- `wish_annotations` 加 `checked_at TEXT DEFAULT ''`；`wish_places` 加 `date TEXT DEFAULT ''`（`target` 自由文本保留但不再作为时间依据）。
- **老库补列必须两张表都补**：`migrateWishChecked()` 原来只补 checked_at，结果 dev 库起不来（`table wish_places has no column named date`，require 阶段 prepare 就崩）。补列必须在预备语句之前。
- upsert 用「传 NULL 保留原值」的 CASE（前端是合并式写入）；要清空必须显式传 `''`。
- 老备份导入不受影响：`insertRowsSafe` 按当前 schema 过滤列，缺列走 DEFAULT ''。

### 前端
- `wishstore.js`：`updateWishPlace` 改成**合并式**（`patch.x != null ? patch.x : p.x`）—— 旧写法 `country || null` 会在只改日期时把国家清成 null、优先级/备注清空。新增 `needsRevisit(p)` / `markRevisitChecked(p)` / `clearRevisitChecked(id)`。
- 判定：`checkedAt !== p.date`（存**日期串**不是时间戳）→ 改期后自动重新提醒。
- `ui.js`：`dueRevisits()` = 心愿清单里「有日期 + 日期已过 + 该日期未确认」，按日期升序；`paintRevisit()` 控 hidden + 角标；浮层 `.rv-pop` 三屏（ask / went / notwent）。
- 分支实现：去了 → A 类 `api.updatePlace(p.id,{...p,type:'旅行'})`（geo.js 点亮口径跳过「目的地」，不转正国家永远不亮），B 类 `api.createPlace` 落地成足迹再 `deleteWishPlace`；加媒体 → `onEditPlace`；没去 → 换时间（A 类走足迹弹窗 / B 类 `openWishEdit`）；不去了 → `setAnn(wish:false)` + 清日期。
- 新增 `onDataChanged` 回调（main.js → refreshData），改完立刻拉全量，不用等轮询。
- `createUI` 导出 `getDueRevisits`（排查角标用，等同 getStats/getView）。

### 关键坑（都踩过）
1. **`updateWishPlace` 末尾 `setAnn(id,{wish:true,...})` 会把「不去了」的 wish:false 顶回 true** → 心愿又回清单。已删掉 wish 字段（wish 不该由地点更新顺带改）。
2. **浮层第二问问错对象**：答完第一问该心愿就出队了，`dueRevisits()[0]` 已经是下一个 → 「要给这次 X 之行加照片」显示的是下一个心愿。修法：`rvStep` 把当前 id 写进 `rvPop.dataset.id`，用 `rvCurrent()` 取；换题统一走 `rvAdvance()`。
3. **`paintRevisit()` 在队列空时会收起浮层** → 队列最后一个心愿的「加不加媒体」永远问不出来。加 `keepOpen` 参数。
4. `.btn{display:inline-flex}` 特异性高于 `[hidden]` → 按钮 hidden 了还戳在那。补 `.rv-btn[hidden]{display:none}`。
5. 验收脚本每轮要 `PUT /wishes/annotations/:id {checkedAt:''}` 重置 —— **注解没有 DELETE 接口**，上轮的 checkedAt 会让下轮同 id 同日期的心愿被当成已确认，队列直接空（我误判成功能 bug 查了半天）。

验收：`npm run preview:revisit`（自动造 3 条到期数据→跑三分支→清数据）；产物 `revisit-{ask,went,notwent,reschedule}.png`。结果：角标 3→2→1、A 类 type 目的地→旅行、第二问对象正确、编辑足迹弹窗预填正确、刷新后不重复问、心愿弹窗日期预填、无 console 错误。`npm run preview:widgets-check` 回归无变化。

## 修两个 bug：编辑地点丢掉封面 / 海报墙翻转时"抽一下"

### ① 编辑日期后封面消失（A 类足迹）
- 现象：用户改了旧金山、东京的日期，心愿清单/海报墙上的图变成类型色占位块。
- 根因：`upload.js:submit()` 的编辑 payload **不含 cover**，而 `createPlace` 的 upsert 里写死
  `cover_url: p.cover ? String(p.cover) : ''` → 任何"只改几个字段"的 PUT 都把已抓好的
  地标封面覆盖成空串。**不是前端 bug，是后端全行覆盖语义**。`color` 同理（自定义颜色也会被清）。
- 修法：`color` / `cover_url` 改成**缺省即保留** —— `createPlace` 里 `p.cover != null ? String(p.cover) : null`，
  ON CONFLICT 用 `CASE WHEN excluded.x IS NULL THEN places.x ELSE excluded.x END`；要清空请走
  `setPlaceCoverUrl(id,'')`（媒体上传后清占位图正是它）。trips.cover_url 同样处理。
- 前端配套：`ui.js` 新增 `placePatch(p, patch)`，别再 `{...p}` 直传 —— 归一化对象里是 `endDate`（camel），
  后端读 `end_date`，直传等于把结束日期清空；cover/color 刻意不发（不发才保留）。
- 存量修复：`src/landmark.js` 新增 `backfillPlaceCovers()`，server.js 启动 1.5s 后后台跑，
  给「没封面 + 没有 ready 媒体」的地点重抓地标图（有媒体的不碰，否则会盖住真实照片）。
  db 侧新增 `placesMissingCover()`。沙箱无外网 → 本机验证只能确认不抛错（24s 后结束）。
  **用户机器重启容器后会自动补回东京/旧金山**，日志 `[cover] 已为 N 个无封面地点补齐地标图`。
- 验证：PUT（不带 cover）→ 封面保留；PUT（cover:''）→ 清空；走真实 UI「没去→不去了」后封面仍在。

### ② 海报墙翻转时整块"抽搐"
- 先排除的假设（都实测过）：布局位移（widget/body/wall 逐帧尺寸 0 变化）、瞬时滚动条
  （`scrollHeight-clientHeight` 恒为 0）、掉帧（15s 902 帧，p99 17.6ms，**零帧 >33ms**，
  连 23 次 transitionend 附近也如此，新旧代码 A/B 都是如此）、整墙重绘（CDP 录屏逐帧 diff，
  变化都落在翻转的那张卡上）。
- 真正原因：**透视投影外溢**。`perspective: 1100px` 下转到 45° 时 2×2 大块会"鼓"出格子约 9px，
  正好压在相邻格之间的 12px 缝里；最左一列贴着墙左缘，鼓出去再收回来，看着像整块墙在抽。
  裁切像素实测：修复前变化包围盒比格子顶部高 9px，修复后 **完全落在格内**（超出量 0）。
- 修法三条：
  1) `.pw { overflow: hidden }` —— 把投影裁在自己格里（静止态像素回归：365500 像素里只有 338 个
     因随机配图不同而变，布局零变化）；
  2) `.pw { perspective: 1100 → 2200 }` —— 外扩幅度减半，保留立体感；
  3) `poster.js` 里 `transitionend` 归零角度时，`void inner.offsetWidth`（会同步整页 layout）
     改成 `getComputedStyle(el).transform`（只解析样式），并把归零动作丢进 `requestIdleCallback`
     —— 别在合成器提交动画最后一帧的那个任务里再写样式。
  另加 `.widget[data-type="poster"] .widget__body { overflow: hidden }`（这面墙永远不需要滚动）。
- 注意：`.widget__body` 自己就是 `.posterwall`（元素同时带两个类），改 overflow 时两处是同一个盒子。

### ③ 愿望地点点亮了美国 + 东京图钉漂到几内亚湾（用户第二张截图）
- 两个现象**同源**：编辑弹窗把「目的地」洗成了「旅行」。
  `upload.js edit()` 里那道"原类型还原"的防御是**死的**：类型下拉只有 居住/旅行（没有「目的地」），
  `select.value='目的地'` 无法选中 → value 变空串 → `editingDefaultSelType = '' || null = null`，
  于是 `selType === editingDefaultSelType` 永远不成立 → 提交时 type 被兜底成「旅行」。
  geo.js 的口径（type==='目的地' 跳过上色）是对的，是数据被污染了。
- 修法：改成按 **change 事件** 判"用户有没有动过下拉"（`typeTouched`），没动过就沿用 `editingType`；
  删掉 `editingDefaultSelType`。别再拿"选中值 vs 回落值"做判断。
- 东京/旧金山的 `lng/lat` 是 **(0,0)**（几内亚湾）—— 创建时没拿到坐标，被 `Number(null)===0` 洗成 0。
  - `src/db.js` 新增 `parseCoord(p)`：缺失/空串/非数字/越界一律返回 null；`createPlace` 更新时
    坐标和 `type` 都改成**缺省即保留**（`prev = stmt.getPlace.get(id)` 兜底），新增才用默认。
  - `ui.js confirmWent()`（B 类心愿落地成足迹）补了国家中心点兜底（`COUNTRY_CENTROIDS`），
    否则没坐标的心愿「去了」之后会落到 (0,0)。
  - 存量数据已修：东京 → 139.6917,35.6895 / JP / 目的地；旧金山 → -122.4194,37.7749 / 目的地。
- 口径备忘：`place.countryCounted` = "这国家算不算进统计"，**不是**"有没有点亮"；
  点亮看 `visited.has(place.countryId)`。图层是 `match` 表达式上色，
  `queryRenderedFeatures` 在任何陆地都命中，验上色要读 `getPaintProperty('tm-country-visited','fill-color')`。
- 新验收脚本 `preview/wish-color-check.js`（`npm run preview:wishcolor`）：6 项全绿，
  含「铃铛 → 没去 → 换个时间 → 只改日期 → 类型/坐标/封面必须保住」的端到端回归。

### ④ 详情弹窗「删除」图标变形（用户第三张截图）
- 现象：胶囊按钮里垃圾桶图标看着"歪/变形"，左壁近乎竖直、右壁斜切。
- 根因在 `web/index.html` 的 `#i-trash` path：桶身用 `m-9 0`（相对移动）从把手末端
  (15,7) 回跳，落到 **(6,7)** —— 盖子 4→20 中心是 12，桶身 6→16 中心是 11，整体偏左 1 单位。
  这是 SVG 相对坐标的经典坑：看着像"随手的 -9"，其实把整段 body 平移错了。
- 修法：改成绝对坐标起笔 `M7 7`（中心 = 12），顺手把桶底收窄（`l1.6 13` + `h2.8`），
  避免像水桶。包围盒尺寸不变（180×210 @240px），只改形状不动体量。
- 量化对比（240px 光栅，镜像 IoU / 重心偏差）：旧 0.378 / 5.52px → 新 **0.999 / 0.01px**。
- 新验收脚本 `preview/icon-check.js`（`npm run preview:icon`）：光栅化 sprite 路径 →
  算墨迹镜像对称度，阈值 IoU ≥ 0.92、重心偏差 ≤ 1px。**改任何 SVG 图标后都该跑一次**，
  肉眼"差不多"在 15px 下经常是错的。
