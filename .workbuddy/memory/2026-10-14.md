## 排查：Windows 裸 docker run 首配向导预填为空
- **现象**：拉取 wyc6036/travelmap:amd64 后单独 docker run，首配向导提示"已填好内置 MinIO 连接信息"，但表单实际为空，点保存报"服务器地址、账号、密码均为必填"。
- **根因**：内置 MinIO 默认值完全来自环境变量（src/storage.js 读 `process.env.MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY`，默认空串），而 Dockerfile 运行阶段未设置这些 ENV —— 它们只在 docker-compose*.yml 的 environment 里注入。裸 docker run 不带 env → 预填空 → 校验失败。
- **修复**：Dockerfile 运行阶段补 `ENV MINIO_ENDPOINT=minio / MINIO_PORT=9000 / MINIO_USE_SSL=false / MINIO_ACCESS_KEY=travelmap / MINIO_SECRET_KEY=changeme-minio-password / MINIO_BUCKET=travelmap`，与 compose 约定一致。需重新 build & push 镜像后生效。
- **Windows 立即解法**：用 docker-compose.prod.yml（需 .env 设 DH_USER/ADMIN_PASSWORD）或 docker run 时补 -e 上述变量并同网络跑 minio 容器。

## 推送 Docker Hub 被网络挡（环境结论）
- **结论**：本机(Mac)推送 docker.io 失败，根因是网络层——直连 `auth.docker.io`/`registry-1.docker.io` 均超时(HTTP 000)；仅有的本地工具代理 127.0.0.1:63300 能出公网(example.com 200)但不通 docker.io 官方域；国内镜像源 docker.1ms.run/docker.m.daocloud.io 可达(401)仅供 pull，不能 push。
- **现象**：`publish.sh wyc6036 v2` 两次均在 "failed to fetch oauth token ... Bad Gateway/超时" 处失败；镜像本身已多架构构建成功，仅差 push。
- **注意**：pull 能成靠的是 docker daemon 配的国内镜像源(只读缓存)；push 必须直连 docker.io 官方，被地域封锁挡住。非代码/Dockerfile 问题。
- **出路**：① 给 Docker 配能连 docker.io 的代理/VPN 后再 publish；② 在能连 docker.io 的机器(如 Windows 端) push；③ 等网络恢复重试。

## 重试推送仍失败（追加 daemon 代理细节）
- 第三次重试仍在 "failed to fetch oauth token ... Bad Gateway" 失败。
- 查 daemon 代理：Docker Desktop 配了 HTTP/HTTPS Proxy=http.docker.internal:3128（转发本机代理链），No Proxy 仅含镜像源，不含 docker.io → push 强制走代理链，对 auth.docker.io 回 502；直连也超时(000)。
- 结论：本机无任何路径可达 docker.io 官方域，push 不可行，须换网络出口或换机器推。镜像本地已多架构构建成功，网络通后重跑 publish.sh 即可。
