## 修复（十）：响应式列数失效 + CDN 自托管（用户确认"1和2一块修"）
- **#1 响应式列数**：`--cols/--cell-h` 默认值从 `widget.css:7` 迁到 `tokens.css` `:root`（最先加载），`widget.css` 删除无条件 `:root{--cols:4}`（只消费不重声明），并留注释说明原因。
  实测 `--cols`：1440/1280→4、900/768→2、620/480/360→1，与 layout.css 媒体查询意图一致；480 移动端截图确认组件通栏单列。
- **#2 CDN 自托管**：`web/vendor/` 新增 maplibre-gl.js(1.03MB, v5.24.0)、maplibre-gl.css(68KB)、Sortable.min.js(44KB)；`index.html` 三处 unpkg/jsdelivr 引用改为 `./vendor/...`；
  `main.js:357` 与 `map.js:141` 的报错文案从"检查 unpkg CDN"改为"确认 vendor 已部署"。
  关键核验：MapLibre v5 的 worker 是 `URL.createObjectURL(new Blob([workerBundleString]))` **内联**的（`.worker.js` 不存在），单文件自托管即可，离线不缺 worker。
  离线模拟验证（Playwright 阻断全部外部请求）：`booted:true`、maplibre/Sortable 均本机加载、PAGE_ERRORS=0；被阻断的外部请求仅 1 个（openfreemap 底图样式，运行时在线服务，预期内）。
  `Dockerfile:93 COPY web ./web` + `.dockerignore` 均不排除 vendor → 随镜像打包；生效需 `docker compose up -d --build`。
  保留的外部依赖（有意不做自托管）：OpenFreeMap 底图样式/瓦片（config.js）、Nominatim 地理编码（upload.js）——在线服务，vendor 化无意义；离线时仅地图无瓦片、应用与组件照常可用。
- 收尾：停止 8126 服务；删除 /tmp/tm_diag*.mjs、/tmp/tm_verify.mjs、/tmp/tm_vendor_dl.mjs 及截图。
