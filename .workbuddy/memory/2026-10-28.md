## 修复：地点详情右栏照片墙「列数塌陷」（杭州 2 列留白 / 天津 正常）

**现象**：同一页面里，天津（14 张，单日）照片 3 列排布正常；杭州（6 张，分 2 天，当日 4 张）只排 2 列、右侧整条留白，且序号顺序变成先竖后横（上排 1、3，下排 2、4）。

**根因**：`.mgrid { columns: 3 }` 用的是 CSS 多列。Chrome 的列平衡在**当天条目少**时会退化成 2 列（第 3 列整条空着），顺序也是"按列自上而下"。所以同一份样式在不同图片数的地点上表现不一致——天津条目多刚好平衡成 3 列，杭州只有 4 张就塌了。与图片比例无关（两地全是 1600×1200）。

**修法**（均在授权范围内：`web/css/modal.css` + `web/js/detail-modal.js`，地图模块未动）：
- `.mgrid` 改为 `display: grid; grid-template-columns: repeat(var(--mgrid-cols), minmax(0,1fr))`，列数由 `--mgrid-cols` 决定（3 / ≤900px 为 2）；新增 `.mgrid__col`（flex 列 + gap 9px），`.mgrid__cell` 去掉 `margin-bottom`。
- `detail-modal.js` 新增 `fillMasonry()`：按 `item.width/height` 的比例把格子逐张放进**当前最矮的一列**（各列等宽，比例即可比较高低，不必等图片加载后测量）；`grid.__masonry` 存 `{cell, ratio}` 供重排；列数没变直接 return，避免白搬 DOM。
- `layoutMasonry()` 在 `renderContent()` 末尾（网格进 DOM 后才算得准列宽与间距占比）调用；`ResizeObserver` 盯 `contentEl`，只在 3↔2 列切换时重排。
- `mediaCell()` 给 `<img>` 补 `width/height` 属性（`mediaDims()`），图片没下载完就先把格子撑到正确高度，避免加载完整体跳一下。
- 结果：4 张 = 上排 1、2、3 + 下排 4（与 CSS grid 行优先一致）；14 张 = 5/5/4 三列均匀；74 张（黄龙，含竖图）三列均衡、原始比例不裁切。

**验收**：新增 `preview/mgrid-check.js` + `npm run preview:mgrid`。
- `-- --local` 会把工作区 `web/` 覆盖容器静态资源（省一次 rebuild）；`-- --place=天津` 换地点。
- 结果：杭州 `usedColumns=3`、宽度 872（(872-18)/3=285 ✓）；窄屏 860px → `--mgrid-cols=2`、wrapper 2 列。
- 已 `docker compose up -d --build` 重建，8080 上的实例即为修复后版本（live 复测同样 3 列）。
- `preview/README.md` 脚本清单已补 `mgrid-check.js` 一行。

**踩坑记录**：终端里 `grep -rn "a\|b" file` 在这台机器上偶尔整条匹配为空（BSD grep 行为），多模式搜索改用 Grep 工具或分开写。

## 旅途海报墙（poster.js/poster.css）去蒙版方案效果图（未改源码）

用户诉求：海报墙不要「蒙版」，改成照片按格子大小**裁切铺满**（cover）。当前实现是 `object-fit: contain` + `.pw__back` 同图模糊衬底（比例留白处露虚化版），视觉上像蒙版。
- 出图脚本 `preview/poster-cover-mock.js`（纯注入 CSS，不改源码）：`--size=2x2|3x2` 切组件尺寸；产物 `preview/poster-mock-{current,a,b}[-2x2].png`。
- 方案A = cover + 保留底部 `.pw__scrim` 渐变与 `.pw__meta` 地名；方案B = cover + 去掉 scrim/meta（纯照片）。
- 实测裁切保留率（线性，按格子宽高比）：3x2 档最扁的块 2.43:1 遇竖图只剩 31%；2x2 档多数 86%，竖块 0.73 遇横图剩 54%。
- 已知小问题（**现状也有**，非本次引入）：窄块里 `.pw__meta` 的「地名 + 日期」会被右边缘截断，flex 子项设了 nowrap 所以 text-overflow:ellipsis 不生效；若采纳 cover 需一并处理（窄块只留地名 / 日期缩成 MM.DD）。
- 唤醒环境：8080 容器当时是停的，`docker compose up -d`（不加 --build）即可。

### 已按方案A落地（用户确认，2026-10-28）

- `web/css/poster.css`：`.pw__media` 改 `object-fit: cover` + `object-position: center`；**删除 `.pw__back` / `.pw__back-img` 全部规则**（毛玻璃蒙版退役）；顶部"两条不能动的约定"补了一句：cover 时代比例温和的意义从"少留白"变成"少裁掉"（3x2 档最扁块 2.43:1 遇竖图线性只剩 31%）。
- `web/js/poster.js`：`paintFace()` 删掉 `.pw__back` 衬底 DOM 与同图加载（每块少一次重复请求）；`pickNext` 注释改为"错配由 pickNext 按朝向挑图兜底"（不再由模糊衬底兜底）。
- **顺手修的 bug**：窄块里「地名 + 日期」被右边缘硬切断。原因：`.pw__meta` 容器 flex + 子项 `nowrap`，`text-overflow: ellipsis` 落不到子项上。改法：容器不再设 nowrap/ellipsis，改为 `.pw__meta b { min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap }` + `.pw__meta span { flex-shrink:0 }` → 地名优先省略、日期完整。
- **没动**：3x2 档最扁块（2.43:1）的比例——改版式要重排整套 `.pw--a~j` span，风险大、收益小，靠 pickNext 朝向匹配缓解即可。
- 验收：`docker compose up -d --build` 后 `node preview/poster-cover-mock.js --plan=none` → `{"objectFit":"cover","backNodes":0,"mediaNodes":10}`；2x2 档截图确认地名已带「…」、日期完整、照片铺满。
