## 修复：地点详情右栏照片墙「列数塌陷」（杭州 2 列留白 / 天津 正常）

**现象**：同一页面里，天津（14 张，单日）照片 3 列排布正常；杭州（6 张，分 2 天，当日 4 张）只排 2 列、右侧整条留白，且序号顺序变成先竖后横（上排 1、3，下排 2、4）。

**根因**：`.mgrid { columns: 3 }` 用的是 CSS 多列。Chrome 的列平衡在**当天条目少**时会退化成 2 列（第 3 列整条空着），顺序也是"按列自上而下"。所以同一份样式在不同图片数的地点上表现不一致——天津条目多刚好平衡成 3 列，杭州只有 4 张就塌了。与图片比例无关（两地全是 1600×1200）。

**修法**（均在授权范围内：`web/css/modal.css` + `web/js/detail-modal.js`，地图模块未动）：
- `.mgrid` 改为 `display: grid; grid-template-columns: repeat(var(--mgrid-cols), minmax(0,1fr))`，列数由 `--mgrid-cols` 决定（3 / ≤900px 为 2）；新增 `.mgrid__col`（flex 列 + gap 9px），`.mgrid__cell` 去掉 `margin-bottom`。
- `detail-modal.js` 新增 `fillMasonry()`：按 `item.width/height` 的比例把格子逐张放进**当前最矮的一列**（各列等宽，比例即可比较高低，不必等图片加载后测量）；`grid.__masonry` 存 `{cell, ratio}` 供重排；列数没变直接 return，避免白搬 DOM。
- `layoutMasonry()` 在 `renderContent()` 末尾（网格进 DOM 后才算得准列宽与间距占比）调用；`ResizeObserver` 盯 `contentEl`，只在 3↔2 列切换时重排。
- `mediaCell()` 给 `<img>` 补 `width/height` 属性（`mediaDims()`），图片没下载完就先把格子撑到正确高度，避免加载完整体跳一下。
- 结果：4 张 = 上排 1、2、3 + 下排 4（与 CSS grid 行优先一致）；14 张 = 5/5/4 三列均匀；74 张（黄龙，含竖图）三列均衡、原始比例不裁切。

**验收**：新增 `preview/mgrid-check.js` + `npm run preview:mgrid`。
- `-- --local` 会把工作区 `web/` 覆盖容器静态资源（省一次 rebuild）；`-- --place=天津` 换地点。
- 结果：杭州 `usedColumns=3`、宽度 872（(872-18)/3=285 ✓）；窄屏 860px → `--mgrid-cols=2`、wrapper 2 列。
- 已 `docker compose up -d --build` 重建，8080 上的实例即为修复后版本（live 复测同样 3 列）。
- `preview/README.md` 脚本清单已补 `mgrid-check.js` 一行。
