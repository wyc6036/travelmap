## CF 公网迁移评估 → 选定 CF Tunnel 零改动方案
- 用户需求：借助 Cloudflare 免费额度把程序迁到公网访问。
- 完整评估过 Workers + D1 + R2 全栈方案：server.js 790 行 + src/db.js（64 处 better-sqlite3 同步调用）+ sharp/ffmpeg 原生依赖，Workers 跑不了原生二进制/子进程；视频转码无免费替代（Stream $5/月）；D1 需同步→异步全量重写。工作量大且要砍功能，**放弃**。
- **最终决策：CF Tunnel 零改动直通**。Express/sharp/ffmpeg/MinIO 原样跑，只是加 cloudflared 边车。用户确认此路径（问答式确认：路径选 Tunnel、接受其无功能取舍）。
- 数据现状（2026-10-19 查库）：media 表 150 张 image 全部 ready、**0 条视频**；minio-data 95MB、data 目录 4.9MB。CF 免费 plan 单请求 100MB body 上限对当前使用模式无影响，大视频走局域网直传（8080 端口映射保留）。
- 交付物：`docker-compose.tunnel.yml`（overlay，TUNNEL_TOKEN 远程配置模式，ingress 走 dashboard 图形化配 http://travelmap:8080）。用法：`docker compose -f docker-compose.prod.yml -f docker-compose.tunnel.yml up -d`。附带 Quick Tunnel 体验命令（trycloudflare.com 临时域名）。
- 环境前提：需域名 NS 托管在 CF + .env 配 CF_TUNNEL_TOKEN；部署机 7×24 常开。

## MinIO 镜像无法拉取 → 更换为 Chainguard 重建镜像
- 用户需求：检查项目里的 minio 镜像是否已无法从 docker 拉取，是则换可用镜像。
- **实证结论：`minio/minio:latest` 确实已下线**。`docker pull minio/minio:latest` → `docker.io/minio/minio:latest: not found`（Docker Hub 可达但 tag 404）。背景：MinIO 官方 2025-10-15 起停止分发 Docker 镜像（社区版改仅源码发布，2025-12 进入维护模式、2026-04 仓库归档），Docker Hub 最后更新停在各 RELEASE.2025-09-07，quay.io 同 tag 已 401。本机只是靠 2024-05 的旧缓存才看起来正常。
- **替换为 `cgr.dev/chainguard/minio:latest`**（Chainguard 从官方源码持续重建的免费版，实测可拉取；当前版本 RELEASE.2026-09-22T19-25-18Z）。入口 `/usr/bin/minio`，compose 的 `command: server /data --console-address ":9001"` 原样兼容；默认非 root（uid 65532），实测对 root 时代创建的 bind mount `./minio-data` 读写正常。
- 改动：`docker-compose.yml` 与 `docker-compose.prod.yml` 的 minio 服务 image 替换（附原因注释）；README 加说明块。Dockerfile 只依赖 `node:20-slim`（官方镜像仍可用，未动）。
- 验证：① minio-data 副本启动无 repair/error；② 项目自带 minio npm 客户端对副本桶 301 对象 listBuckets/listObjects/putObject/getObject/removeObject 全过；③ 真实 compose 栈 `docker compose up -d minio` 起真实数据，mc 容器经 compose 网络列出 301 个对象；④ 测完 `docker compose down`，环境恢复无容器状态。真实 `./minio-data` 未被测试污染。
- 沙箱注意：Docker 守护进程代理是 `http.docker.internal:3128`（Docker Desktop 内），与 shell 的 `HTTP_PROXY`（127.0.0.1:5xxxx，会 502）不是同一个；docker pull 走前者可用。本机 curl 访问 Docker Hub API 直连/代理均不通，判断镜像是否存在只能靠 `docker pull` 实证。
