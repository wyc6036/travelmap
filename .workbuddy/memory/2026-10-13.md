## 修复：统计页「次旅行」KPI 与探索面板里程图标缺失（空方框）

**现象**：统计页 KPI 卡「2 次旅行」左侧浅蓝圆角方块内无图标，渲染为空 `<svg>` 框。

**根因**：`js/stats.js` 用 `icon('route')`（helper line 39 生成 `<svg class="ico" viewBox="0 0 24 24"><use href="#i-route"/></svg>`）。
使用点：
- `js/stats.js:166` KPI「次旅行」`ico: 'route'`
- `js/stats.js:189` 探索面板里程 `ico: 'route'`

但 `web/index.html` 的 `.svg-sprite` `<defs>` 里**没有定义 `#i-route` 符号**。
`.ico` 是描边型（base.css: `fill:none; stroke:currentColor; stroke-width:1.7`），缺失符号时浏览器只渲染带 viewBox 的空框 → 视觉上「方框里没图」。

**修复**：在 `web/index.html` sprite `<defs>` 内（`i-trash` 之后）补一个描边型路线图标：
```html
<!-- 路线：起点/终点两枚圆点 + 蜿蜒路径 + 指向终点的箭头，对应"次旅行/里程" -->
<g id="i-route"><circle cx="6" cy="18" r="2.2"/><circle cx="18" cy="6" r="2.2"/><path d="M8.2 15.8h7a2.5 2.5 0 0 0 2.5-2.5V8.2"/><path d="M16.8 10.4 19 8.2l2.2 2.2"/></g>
```
（24×24 viewBox、纯 stroke、无 fill，风格与既有图标一致。）

**全盘审计结论**：`route` 是唯一「被使用但未定义」的图标名。审计方式：
- sprite 定义：`grep -oE 'id="i-[a-z]+"' index.html`
- 使用点：grep `ico: '...'` / `icon('...')` + 全部原始 `<use href="#i-...">`
- `comm -23 used defined` 为空 → 无其它缺失。

**验证**：8099 测试服务（`PORT=8099 DATA_DIR=/tmp/tm-test-data`）→ agent-browser 打开 → 点 `button.nav__item[data-view="stats"]` → 截图 /tmp/stats-route.png。
放大 KPI 卡「2 次旅行」与里程行「2,875 公里」两处均正确显示路线图标（蜿蜒路径 + 双圆点 + 箭头），描边风格协调。

**环境备忘**：agent-browser 路径 `/Users/wyc/.workbuddy/binaries/node/versions/22.22.2-6/bin/agent-browser`，用前 `export NO_PROXY=localhost,127.0.0.1`；curl localhost 需 `--noproxy '*'`。

## 修复 ②：新加的 route 图标「错位/偏小」

**现象**：用户反馈「新加的图标错位了」。

**量化定位**（关键方法，以后诊断图标对位可复用）：
在 8099 页面用 `agent-browser eval` 读每个 KPI 图标的 `<use>` 的 `getBBox()`（返回的是 24×24 viewBox 坐标系里的墨迹包围盒）：

| 图标 | 墨迹中心 | 墨迹尺寸 |
|---|---|---|
| globe | 12, 12 | 18.4×18.4 |
| pin | 12, 12.25 | 16×19.5 |
| **route（旧）** | **12.5, 12** | **17.4×16.4** |
| image | 12, 12 | 18×18 |

→ 旧 route 的墨迹中心偏右 0.5 个单位（`cx=12.5`），且尺寸只有 17.4 明显偏小。**根因**：那个「指向终点的箭头」把墨迹右边界推到 x=21.2，而左边界才 3.8，导致包围盒整体右移；再加上斜向构图重心偏右上，视觉上就是「错位 + 显得小」。

**修复**：重设计为**关于 (12,12) 点对称**的路线图标 —— 两枚端点圆点 + 圆角肘形（Z 形）路径：
```html
<g id="i-route"><circle cx="5" cy="19" r="2.4"/><circle cx="19" cy="5" r="2.4"/><path d="M6.4 17.6H9.4A2.6 2.6 0 0 0 12 15V9A2.6 2.6 0 0 1 14.6 6.4H17.6"/></g>
```
点对称 ⇒ 墨迹包围盒天然以 (12,12) 为中心、尺寸 18.8×18.8（与 globe 18.4 同档），自动和其余图标对齐。肘形半径 2.6，两段圆弧 sweep 相反（0 与 1），因为第二段是第一段的 180° 旋转像（旋转保向、反向翻转 sweep）。

**验证**：`eval` 复测 → route 变为 `cx=12, cy=12, 18.8×18.8`；把 4 个 KPI 图标裁出 8× 放大并排对比（globe/pin/ROUTE/image）视觉一致、居中对齐；小号 `ico--sm` 里程行图标同样正常；`errors`/`console` 均无报错。

**经验**：sprite 图标「被 `<use>` 引用后视觉不居中/偏小」，多半是**墨迹包围盒没围绕 (12,12)**（多一个朝单侧的箭头/尾巴就会把 bbox 拽偏）。诊断就用 `use.getBBox()` 读墨迹中心与尺寸，而不是肉眼估。设计图标时让构图保持点对称最省心。
